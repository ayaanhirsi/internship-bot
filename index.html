How it works

Four pieces, all free:

  1. A Python script (notify.py) that checks job sources and finds roles matching your keywords.
  2. A Discord webhook, a private URL that lets the script post into one channel of your server.
  3. A memory file (seen.json) listing every role already sent, so you never get repeats.
  4. GitHub Actions, GitHub's free robot that runs the script on a schedule, so your computer can stay off.
Before you startYou need a free GitHub account, a Discord server where you can make channels, and Python installed if you want to test on your own computer first (optional).
01

Make the Discord webhook

  1. Open your Discord server and create a text channel, for example #internship-alerts.
  2. Click the gear icon next to the channel name, then Integrations, then Webhooks, then New Webhook.
  3. Name it whatever you like, make sure it points to your new channel, then click Copy Webhook URL.
  4. Paste that URL somewhere private for now, like a notes app. You will need it in step 05.
Never share this URLAnyone who has it can post in your channel. Do not paste it in a chat, a screenshot, a public repo or a LinkedIn post. If it leaks, go back to Webhooks, delete it and create a new one. It takes ten seconds.
02

Create the GitHub repo

  1. Go to github.com, click the + in the top right, then New repository.
  2. Name it something like internship-bot.
  3. Choose Private so nobody else can see your setup.
  4. Tick Add a README file and click Create repository.
03

Add the three files

You can do all of this in the browser: in your repo click Add file, then Create new file, paste the content, and click Commit changes.

File 1: notify.py

This is a simple starter version. Replace the SOURCES and KEYWORDS with the job feeds and words you care about. Each source should return a list of jobs with a title, company and link.

notify.py
import json
import os
from pathlib import Path

import requests

WEBHOOK = os.environ["DISCORD_WEBHOOK"]
SEEN_FILE = Path("seen.json")
MAX_PER_RUN = 15

# Words a job title must contain (any one of them)
KEYWORDS = ["intern", "co-op", "student"]

# Replace with your own sources (JSON feeds that return a list of jobs)
SOURCES = [
    "https://example.com/jobs.json",
]


def load_seen():
    if SEEN_FILE.exists():
        return set(json.loads(SEEN_FILE.read_text()))
    return set()


def fetch_jobs():
    jobs = []
    for url in SOURCES:
        try:
            r = requests.get(url, timeout=30)
            r.raise_for_status()
            jobs.extend(r.json())
        except Exception as e:
            print(f"source failed: {url} ({e})")
    return jobs


def matches(job):
    title = job.get("title", "").lower()
    return any(k in title for k in KEYWORDS)


def main():
    seen = load_seen()
    jobs = [j for j in fetch_jobs() if matches(j)]
    new = [j for j in jobs if j.get("url") and j["url"] not in seen]
    print(f"matched {len(jobs)}, new {len(new)}")

    sent = 0
    for job in new[:MAX_PER_RUN]:
        msg = f"**{job.get('title')}** at {job.get('company', 'Unknown')}\n{job['url']}"
        r = requests.post(WEBHOOK, json={"content": msg}, timeout=30)
        if r.status_code in (200, 204):
            seen.add(job["url"])
            sent += 1
    print(f"sent {sent} new roles")

    SEEN_FILE.write_text(json.dumps(sorted(seen), indent=2))


if __name__ == "__main__":
    main()

File 3: the workflow

GitHub only recognizes workflows inside a folder called .github/workflows/. If you save the file at the top level of the repo, it will never appear in the Actions tab.

When you click Create new file, type the full path into the filename box: .github/workflows/alerts.yml. Typing the slashes creates the folders automatically.

.github/workflows/alerts.yml
name: internship-alerts

on:
  schedule:
    - cron: "0 12-22 * * *"   # hourly, about 8am-6pm Toronto time
  workflow_dispatch:           # adds a manual "Run workflow" button

permissions:
  contents: write

concurrency:
  group: internship-alerts
  cancel-in-progress: false

jobs:
  alerts:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - run: pip install requests

      - name: Run notify.py
        env:
          DISCORD_WEBHOOK: ${{ secrets.DISCORD_WEBHOOK }}
        run: python notify.py

      - name: Save seen.json
        run: |
          git config user.name "alerts-bot"
          git config user.email "alerts-bot@users.noreply.github.com"
          git add seen.json
          git diff --cached --quiet || (git commit -m "update seen" && git push)
Already saved it in the wrong place?Click the file, click the pencil icon, change the filename box to .github/workflows/alerts.yml, then commit. This renames the file instead of copying it, so you will not end up with a duplicate.
04

Add your webhook as a secret

This is how the bot gets your Discord URL without it ever being written in your code.

  1. In your repo, click Settings.
  2. In the left sidebar open Secrets and variables, then Actions.
  3. Click New repository secret.
  4. Name: DISCORD_WEBHOOK (exactly, all caps). Secret: paste your webhook URL.
  5. Click Add secret.
Leaked it by accident?Delete that webhook in Discord, make a new one, and update the secret. Always use the newest URL.
05

Run it for the first time

  1. Click the Actions tab in your repo. If GitHub asks, click the green button to enable workflows.
  2. In the left sidebar click internship-alerts.
  3. Click Run workflow, then the green Run workflow button.
  4. Wait about a minute and refresh. A green check means success. Then look at your Discord channel.

Reading the result

Click the run, then the job, then expand the Run notify.py step. It prints a line like matched 37, new 15 and sent 15 new roles.

What you seeWhat it means
Green check + messages in DiscordEverything works.
Green check, empty channelNothing new matched, or your sources are not loading. Check the "matched" number.
matched 0A source URL is wrong or your keywords are too narrow.
Red XClick the failed run and read the error. Common causes: the workflow file is in the wrong folder, or the secret name is misspelled.
Two yellow warningsNode.js and Ubuntu notices from GitHub itself. Harmless, ignore them.
06

Make it run automatically

The schedule is the cron line in your workflow. Seeing on: workflow_dispatch on a run only means you started it manually. The cron line is what makes it run on its own.

CronHow often
0 12-22 * * *Every hour during the day (recommended)
0 */3 * * *Every 3 hours, around the clock
0 */6 * * *Every 6 hours
0 13 * * *Once a day at 9am Toronto time

To change it, open .github/workflows/alerts.yml, click the pencil icon, edit the cron line and commit. It takes effect on its own.

Good to know

  1. Cron uses UTC. 12:00 UTC is 8am Toronto in summer and 7am after the clocks change in November.
  2. GitHub runs late. Scheduled runs often start 10 to 30 minutes after the time you set, and may occasionally skip one.
  3. Free minutes. Private repos get 2,000 free Actions minutes a month. One run takes about a minute. Hourly during the day is roughly 330 minutes a month. Every 30 minutes around the clock would use almost all of it, so I would not go that high.
  4. The 60-day pause. GitHub pauses scheduled workflows on repos with no activity for 60 days. The bot commits seen.json whenever it finds new roles, which usually keeps it alive. If alerts stop, open the Actions tab and re-enable the workflow.
07

Questions I actually had

Will it send the same roles again and again?

No. Every run checks each role against seen.json. Roles already on the list are skipped. New ones are sent and then added to the list. The only way to get repeats is if the final step fails to save seen.json back to the repo, so check that step if you ever see duplicates.

Why is my Discord channel quiet?

If nothing new was posted since the last run, the bot sends nothing. That is normal. Open the run log and look for the matched line to confirm it is checking.

Why did it only send 15 roles?

The script caps each run at 15 so Discord is not flooded. The rest are not marked as seen, so they arrive on the next run. Nothing is lost.

Do I need to keep my computer on?

No. GitHub runs it in the cloud, so your computer can be off or closed.

Why did the workflow not show up in the Actions tab?

Almost always because the file is not inside .github/workflows/. See step 03 to move it.

What is __pycache__ and should it be in my repo?

It is a folder Python creates when you test locally. It is harmless but unnecessary. From your project folder run git pull, then echo __pycache__/ >> .gitignore, git rm -r --cached __pycache__, git add .gitignore, git commit -m "ignore pycache" and git push. Run git pull first because GitHub now has commits your computer does not.

I pasted my webhook somewhere public. Now what?

Delete it in Discord (Integrations, Webhooks), create a new one, and update the DISCORD_WEBHOOK secret in GitHub.

Can I add more companies or keywords?

Yes. Add sources to the SOURCES list and words to KEYWORDS in notify.py, then commit. The next run uses the new settings.
